# MyDocs

Lightweight document manager: vanilla HTML/CSS/ES modules, SQLite metadata, files in app-private storage, packaged for Android with Capacitor 8 (iOS-ready architecture, not yet built or tested).

## Layout

| Path | Purpose |
|---|---|
| `www/index.html`, `css/styles.css` | Dashboard UI (no remote resources, strict CSP) |
| `www/js/app.js` | UI only: rendering, events, error toasts |
| `www/js/database.js` | SQLite driver, schema/migrations (`PRAGMA user_version`), transactions, default categories |
| `www/js/documents.js` | Document service (import, list, rename, delete, open, reconcile) + Capacitor adapters |
| `www/js/seed.js` | The 12 categories and demo document metadata |
| `www/js/nav.js`, `www/js/menu.js` | Left navigation drawer component; menu items + Settings structure as data |
| `www/js/zip.js` | Streaming ZIP writer + safe entry names (no dependencies) |
| `www/js/selection.js` | Id-based multi-selection state for the All Documents tab |
| `www/js/search.js` | Search query normalisation and date parsing (pure functions) |
| `www/js/transitions.js` | Category open/close container-transform animation (Web Animations API) |
| `www/js/images.js` | Thumbnail generation (browser canvas) |
| `www/js/mock.js` | In-memory sample data used **only** in a desktop browser |
| `android/` | Generated by Capacitor (`npx cap add android`) |
| `tests/` | Node tests for the database/document logic |

Plugins: `@capacitor-community/sqlite`, `@capacitor/filesystem`, `@capawesome/capacitor-file-picker`, `@capacitor/file-viewer`, `@capacitor/camera`, `@capacitor/app` (Android Back button), `@capacitor/share` (document sharing) (all declare `@capacitor/core >= 8`). The app uses them through `Capacitor.Plugins` (no bundler); only `documents.js` / `database.js` touch them.

## Prerequisites

- Node.js 20+ (developed on 24), npm
- JDK 21 (Capacitor 8 / Android Gradle plugin requirement). Point `JAVA_HOME` at it.
- Android Studio with Android SDK Platform 36 and build-tools; set `ANDROID_HOME`

## Develop

```bash
npm install
npm run dev        # http://localhost:8080, browser preview with sample data (no SQLite/file access)
npm test           # logic tests on Node's built-in SQLite
```

Native SQLite, file storage, picker and viewer only work in the Android app.

## Android

```bash
npx cap sync android     # copy www/ and plugins into android/ (run after every web change)
npx cap open android     # open in Android Studio, then Run on emulator/device
```

Debug APK (output: `android/app/build/outputs/apk/debug/app-debug.apk`):

```bash
npm run apk:debug        # sync + gradlew assembleDebug  (requires JDK 21 + Android SDK)
```

### Release / Play Store

1. Generate an upload key once and **keep it out of git** (`*.jks`, `*.keystore`, `keystore.properties` are ignored):
   `keytool -genkeypair -v -keystore mydocs-upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000`
2. Add a `signingConfigs.release` block in `android/app/build.gradle` reading passwords from an untracked `keystore.properties`.
3. Bump `versionCode`/`versionName` in `android/app/build.gradle`.
4. `cd android && ./gradlew bundleRelease` -> `app/build/outputs/bundle/release/app-release.aab`; upload it to Google Play Console (enable Play App Signing).

The app ID is `com.alichade.mydocs` (`capacitor.config.json`); change it before first publishing if you want a different, owned ID (also update the Android package via `npx cap sync` after editing and renaming the Java package/`namespace` in `android/app/build.gradle`).

## Dashboard data

The dashboard shows 12 categories (see `seed.js`). Each ships with sample documents marked `is_demo` (metadata only, no files); tapping one shows a "sample data" message. Real imports are stored separately and are never demo. Schema is at v2; databases created by v1 are upgraded in place.

## Camera

"Capture with Camera" opens the system camera app (no CAMERA permission is requested), previews the photo, asks for a name, then saves a JPEG plus a small thumbnail in app-private storage. In the browser preview a generated sample image stands in for the camera.

## Search

The header search icon expands into a field. Results update as you type across all categories, by name (partial, case-insensitive) or by date (`2026-10-17`, `17/10/2026`, `17 Oct 2026`, ...). Documents with the same name are listed separately with their category and date.

## Menu and Settings

The hamburger icon in the header opens a left navigation drawer. To add a destination: add an entry to `MENU_ITEMS` in `www/js/menu.js` and a handler under `destinations` in `www/js/app.js`. Settings rows come from `buildSettingsSections()` in `menu.js`.

## All Documents and ZIP sharing

The bottom tabs switch between **Category** (the dashboard) and **All Documents** (every saved document grouped by category, with checkboxes). **Share Files** bundles the selected documents into one `MyDocs_<date>.zip` (entries `Category/Name.ext`, duplicate names get `(2)`...) in the app cache and opens the Android share sheet. Sample documents have no file and cannot be zipped.

## Sharing

The share icon on a document card opens the Android share sheet with the real file attached (PDF, image, ...). A temporary copy named after the document is placed in the app cache and exposed through a FileProvider `content://` URI with a temporary read grant; it is replaced on the next share and cleared on app start.

## Data and security notes

- Metadata lives in on-device SQLite (`mydocs`); files are copied to app-private `Directory.Data/documents/<uuid>.<ext>`.
- Neither is encrypted by the app; protection is Android's app sandbox and device encryption only.
- Document names/contents are not logged.
- Imports read the picked file as base64 (limit 25 MB). Supported: pdf, jpg/jpeg, png, webp, gif, txt, doc, docx.

## iOS later

UI is platform-independent. Before an iOS release: `npm i @capacitor/ios && npx cap add ios`, confirm each plugin's iOS support, check `FileViewer`/`FilePicker` behaviour, and test on a Mac.
